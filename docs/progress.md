- 2026-09-15 — **M3 Google auth written** (plan M3 steps 1–4), host-agnostic in `src/google/` (no `logseq` import; `fetch`, `sleep`, storage and credentials are injected) and unit-tested against a scripted fake `fetch`:
  - Step 1 `credentials.ts`: `resolveClientCredentials(builtIn, settings)`: a settings override wins but must be complete (ID **and** secret), otherwise the built-in `.env.local` pair; both missing → an error that points at Settings → Advanced. Read lazily on every use so a settings change applies without a reload.
  - Step 2 `oauth.ts` + `ui/ConnectBox.tsx`: `POST /device/code` (scope `drive.file` only), poll `POST /token` at `interval`, `slow_down` → +5 s (RFC 8628 §3.5), `access_denied` → "denied", `expired_token` or the local deadline → "expired", cancel via an `AbortSignal`-aware sleep. The panel shows the code, an "Open in browser" button (`App.openExternalLink`), Copy (clipboard, with a fallback toast), the expiry countdown and Cancel; a sticky toast (`key: gdsync-connect`) repeats the code while the overlay is closed. Polling lives in the auth service, so closing the panel does not interrupt it.
  - Step 3 `tokenStore.ts` + `auth.ts`: one JSON string at `FileStorage` key `auth/google-session.json` (`{version:1, accessToken, refreshToken, expiresAt, scope, account, connectedAt}`). Refresh when < 60 s remain and once on a 401 (single-flight); `invalid_grant` / `unauthorized_client` drop the session (`signed-out` with `reason: 'session-expired'`, toast). Sign-out revokes the refresh token (best effort, warning toast with the myaccount.google.com link on failure) and always clears locally. `restore()` at startup is offline (no network call) so the connected state survives a restart.
  - Step 4 `http.ts`: one `fetch`-based client; backoff `min(32 s, 1 s·2^n) + jitter(0–1 s)`, max 5 retries, on 429, 5xx and 403 with a Drive rate-limit reason (`userRateLimitExceeded`, `rateLimitExceeded`, `sharingRateLimitExceeded`); `Retry-After` honoured up to 60 s; network failures retried twice. OAuth 403s (`slow_down`, `access_denied`) and 428 are never retried. Bodies must be re-sendable (string/URLSearchParams/Blob/ArrayBuffer), a contract M4 uploads must respect.
  - Account e-mail: `drive.file` carries no identity and `userinfo` would need extra scopes, so it comes from Drive `about.get?fields=user(emailAddress)` (`account.ts`, works under `drive.file`, spike H3c). If that call fails right after sign-in (e.g. Drive API not yet enabled) the session is kept with `account: null`, the panel shows "unknown account" plus a warning toast, and `restore()` retries the lookup on the next start.
  - Wiring: `src/logseq/googleHost.ts` builds the service from `window.fetch`, `logseq.FileStorage` and `import.meta.env`; `main.tsx` awaits `auth.restore()` before the "sync on startup" check. The M2 mock controller now delegates `connect` / `cancelConnect` / `signOut` to the real auth and mirrors `auth.state` into `status.account` / `status.deviceFlow` (new `SyncStatus` field; `deriveSyncState` unchanged, connecting shows as signed-out). `SyncController` gained `cancelConnect()`. Demo "Show state" buttons keep the real account when one exists.
